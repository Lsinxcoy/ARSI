Reinforcement 01质量管线 + 课程调度（论文④ NeoHorse-1）

NeoHorse 的核心发现：生产流量的真实交互比合成数据高 6.26 分。ARSI 已有三个 agent 的真实轨迹，但没有质量过滤和难度调度。

1.1 轨迹质量三道闸

# src/arsi/foundation/quality_gate.py class TraceQualityGate: """NeoHorse-inspired quality pipeline for trace ingestion.""" def structural_check(self, trace: dict) -> tuple[bool, str]: """Gate 1: Structural validation.""" # Required fields present if not trace.get("action"): return False, "missing_action" if not trace.get("outcome"): return False, "missing_outcome" # Effect in valid range effect = trace.get("effect", None) if effect is None or not (-1 <= effect <= 1): return False, "invalid_effect" return True, "ok" def semantic_score(self, trace: dict) -> dict: """Gate 2: Six-dimension semantic evaluation.""" # LLM-based scoring (or heuristic fallback) return { "goal_achievement": "PASS|WARN|FAIL", "instruction_following": "PASS|WARN|FAIL", "tool_usage": "PASS|WARN|FAIL", "evidence_consistency": "PASS|WARN|FAIL", "error_recovery": "PASS|WARN|FAIL", "termination": "PASS|WARN|FAIL", } def difficulty_label(self, trace: dict) -> str: """Gate 3: C0-C3 difficulty classification.""" # C0: simple/repetitive C1: standard # C2: complex/multi-step C3: novel/ambiguous action = trace.get("action", "") effect = trace.get("effect", 0.5) outcome = trace.get("outcome", "") if outcome == "failure" and effect < 0.3: return "C2" # Hard task that failed elif outcome == "success" and effect > 0.8: return "C1" # Standard task done well elif effect < 0.4: return "C2" # Low effect suggests difficulty else: return "C0" # Default

Reinforcement 02调度层升级（论文② MetaRSI）

MetaRSI 的核心发现：调度本身值 3.6 分。ARSI 的 DimensionManager 需要从"选维度"升级为"真正的调度器"。

2.1 算子化：九个维度 = 九个可调度算子

# src/arsi/governor/operator_scheduler.py class ImprovementOperator: """A schedulable improvement operator (one empowerment dimension).""" def __init__(self, dimension, cost: float, expected_gain: float): self.dimension = dimension self.cost = cost # estimated cost self.expected_gain = expected_gain # estimated benefit self.last_used_generation = 0 self.signal_freshness = 1.0 # MetaRSI Law 2 class OperatorScheduler: """MetaRSI-inspired two-axis scheduler. Horizontal: which operators to apply, in what order Vertical: rewrite each operator's proposal policy """ def schedule(self, operators, budget, generation) -> list: """Select operators based on MetaRSI rules.""" # Rule 1: Signal freshness (Law 2) # Operators used after a capability change have stale signals fresh_ops = [op for op in operators if op.signal_freshness > 0.3] # Rule 2: Cost-benefit ratio scored = [(op, op.expected_gain / max(op.cost, 0.01)) for op in fresh_ops] # Rule 3: Budget constraint selected = [] remaining = budget for op, score in sorted(scored, key=lambda x: -x[1]): if op.cost <= remaining: selected.append(op) remaining -= op.cost return selected def mark_capability_change(self, operators): """MetaRSI Law 2: capability change invalidates prior signals.""" for op in operators: op.signal_freshness *= 0.5 # Decay freshness

关键洞见
MetaRSI 实验：三个算子单独跑差距只有 3.8 分，完整系统多出 3.6 分全部来自调度本身。ARSI 的 Governor 不只是"选一个动作"，而是需要一个决定"哪个维度、什么顺序、多少预算"的调度层。

Reinforcement 03历史即模拟器（论文③ Dream-RSI）

Dream-RSI 的核心发现：历史必须作为可交互的重放模拟器来用，而不是当方向性建议。ARSI 的 brief 应该返回可查询的历史数据，而不是建议文本。

3.1 Brief 升级：从建议文本到可查询模拟器

# src/arsi/adapters/bidirectional_interface.py — 升级 brief class ARSIBrief: """Upgraded brief: returns queryable history, not just advice text.""" def __init__(self, ...): # ... existing fields ... self.history_simulator = None # Dream-RSI: replay simulator def query_history(self, task_type: str) -> dict: """Agent can query: 'what happened historically with this type of task?'""" # Returns structured data, not advice text return { "task_type": task_type, "historical_success_rate": 0.72, "common_failures": ["missing_validation", "premature_finish"], "recommended_approach": "validate_before_complete", "sample_size": 45, "confidence": 0.8, } # In the brief() method: def brief(self, task_description, agent_id): # ... existing code ... # Dream-RSI: build history simulator from discovery tree tree = self.arsi.discovery_tree if tree.nodes: history = self._build_history_simulator(tree, task_description) brief.history_simulator = history return brief def _build_history_simulator(self, tree, task_type) -> dict: """Build queryable history from discovery tree (Dream-RSI style).""" # Find relevant nodes by action category relevant = [n for n in tree.nodes.values() if task_type.lower() in n.action.lower()] if not relevant: return {"available": False} successes = sum(1 for n in relevant if n.outcome == "success") failures = [n for n in relevant if n.outcome == "failure"] return { "available": True, "success_rate": successes / max(len(relevant), 1), "sample_size": len(relevant), "common_failure_patterns": self._extract_failure_patterns(failures), "best_practice": self._extract_best_practice(relevant), }
Dream-RSI 消融实验的教训
把历史当作方向性建议注入提示词，反而持续劣于不用引导的版本。历史必须作为可交互的重放模拟器——agent 可以问"如果我用策略 X 做这类任务，历史表现如何？"而不是"给我建议"。

Reinforcement 04增益三分解升级（论文②定律五）

MetaRSI 定律五：回路不创造能力，所有增益都是进口的。ARSI 需要严格区分三类增益来源。

4.1 三类增益的精确标记

# src/arsi/sealed_eval/gain_decomposition.py — 升级 class GainSource(str, Enum): AMPLIFIED = "amplified" # 已有能力的改进 IMPORTED = "imported" # 从外部导入的新知识 SELF_ORGANIZED = "self_organized" # 系统重组带来的改进 class EnhancedGainDecomposer: """MetaRSI Law 5: every gain is either amplified or imported.""" def decompose(self, traces, before_eval, after_eval): # ... existing rule-based + LLM logic ... # NEW: Mark each gain with its source for t in traces: action = t.get("action", "") params = t.get("params", {}) if params.get("source") == "empowerment": t["gain_source"] = GainSource.IMPORTED elif action.startswith(("evolve", "reflect")): t["gain_source"] = GainSource.AMPLIFIED elif action.startswith(("dream", "maintain")): t["gain_source"] = GainSource.SELF_ORGANIZED else: t["gain_source"] = GainSource.AMPLIFIED return { "amplified": ..., "imported": ..., "self_organized": ..., "source_marked_traces": traces, }

核心原则

四篇论文合起来的判断：RSI 的增益不来自模型变大，而来自回路变好。 ARSI 的强化方向不是加更多功能，而是把已有的回路做得更精细——质量更高、调度更准、历史用得更好、增益归因更诚实。
